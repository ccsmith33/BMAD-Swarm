## Findings

### M-1 (medium; blocking before T4 "Brain core" is closed) — the brain validation/eviction library has zero production callers
`validateBrain` / `evictToBudget` / `parseBrain` are imported **only by tests**. `cli/validate.js` and `cli/doctor.js` contain no brain reference (`grep -rln brain cli/` → empty). Spec §4.4 line 239 requires the budget be "enforced as advisory lint (word-count proxy in `validate`)"; line 250 requires "`doctor` gains a brain check — every file path resolves, every cited D-ID exists"; T4's deliverable list names "`cli/validate.js` + `cli/doctor.js` brain checks." **At HEAD none of that is invocable outside the test suite** — so in a running pipeline the budget/eviction/pointer logic enforces nothing; enforcement is entirely the orchestrator prompt + the pre-compact steering. The library itself is correct and well-tested; it is simply not wired. If a later SE-2 commit wires validate/doctor, downgrade to informational. *Files:* `utils/project-brain.js` (no importers), `cli/validate.js`, `cli/doctor.js`.

### M-2 (medium) — `estimateTokens` measures different strings in `validateBrain` vs `evictToBudget`
`validateBrain` measures `estimateTokens(rawFileText)`; `evictToBudget` measures `estimateTokens(joinFrontmatter(parsed) + rebuiltBody)`, where `joinFrontmatter` re-serializes frontmatter via `yaml.dump` (mutates: ISO `updated` gains `.000`, flow mappings like `staleness: {…}` become block, key spacing changes) and `rebuildBody` collapses blank runs. Measured **402 vs 405** tokens on a trivial brain; the delta grows with nested frontmatter (`gates:`/`staleness:`). The module comment (lines 51–53) asserts the proxy is "the number the budget gate and the eviction loop both use," but they operate on different serializations, so near the boundary `evictToBudget` can report `underBudget:true` while a subsequent `validateBrain` on the written file reports `overBudget:true` (and the re-dumped frontmatter would corrupt `updated`/flow-style if ever written back). Impact is latent today (nothing writes from evict output, nothing wires validate) but becomes real the moment M-1 is fixed. *Fix:* measure eviction against the original raw frontmatter block (a slice) instead of a `yaml.dump` round-trip, or share one canonical serializer between both functions. *File:* `utils/project-brain.js:263,272,284–287`.

### L-1 (low, advisory) — per-SendMessage node spawn + full-ledger read
`task-ledger-writer` runs as a fresh node process on every matched tool call, and every SendMessage does `readFileSync(task-ledger.md)` + O(lines) map rebuild even when no row results. Inherent to the hook design and accepted by the spike; on a busy swarm it adds per-message latency and grows with ledger size. No action required. *File:* `task-ledger-writer.cjs.src:99–131`.

### L-2 (low, informational) — redundant owner on the `created` row
`onTaskCreate` emits `created` carrying `owner=` (when `ti.owner` set) *and then* a separate `assigned` row; the created row already binds owner→task for the join, so the assigned row is redundant for map-building (harmless, arguably clearer as an explicit event). *File:* `task-ledger-writer.cjs.src:76–80`.

### Observation (non-finding) — in-repo `.claude/hooks/` is stale
The dev repo's own `.claude/hooks/` holds only the 4 original hooks (missing `ledger-write-guard`, `replay-gate`, and the 3 SE-2/brain hooks). This is the dogfood install (regenerated by scaffold/`update`), not committed code, so it does not affect the shipped generators — but the framework is not currently running its own SE-1/SE-2 hooks. Recommend the orchestrator regenerate. Not blocking.

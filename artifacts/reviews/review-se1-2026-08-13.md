- **Reviewer:** reviewer-resilience (correctness + coverage lens; bypass-hunting owned by security sibling)
- **Date:** 2026-08-13
- **Scope:** `git diff 9c00390..HEAD` — commits 04fcb8e (prep split), 0490f58 (Fork A), 931d0e3 (ledger), 1f953e1 (replay gate)
- **Lenses:** code-quality, test-coverage
- **Specs:** ADR-017, ADR-021, ADR-022, `artifacts/design/phase2-enforcement-resilience-2026-08-13.md`, D-049

## Verdict: CHANGES REQUIRED

Three high-severity findings: (1) the ledger migration silently dropped the first decision-trail entry of every finding — the committed `ledger.md` has lost 15/24 findings' entire trails; (2) the write-gate's Bash redirect detector fires on `>` inside quoted arguments, hard-denying legitimate allowed commands (`rg "value > 5"`, `git commit -m "a -> b"`, `git log --grep="x>y"`) — all verified empirically; (3) `record.cjs append --status promoted` mints an L-record at `promoted` with no `--human-approved`, bypassing the ADR-021 "non-negotiable" human gate — verified empirically.

Everything else is solid: 604/604 tests reverified green; byte-identity holds for the three unchanged hooks; 20-way concurrent append allocates distinct IDs; the allow-list-first command refusal never executes non-allowlisted commands; the F-017 traversal fixtures are all denied while legitimate paths and teammates pass through; the real `swarm.yaml` parses correctly under the constrained YAML reader.

## 1. Fork A false-positive matrix (verify item 1)

Empirically probed the generated gate (`AGENT_ROLE=orchestrator`, main-thread payload):

| Command | Result | Assessment |
|---|---|---|
| `git status` / `git log` / `git diff HEAD~1 -- "src/a.js"` | PASS | correct |
| `ls`, `grep -rn foo src/`, `cat swarm.yaml`, `npm test`, `npm test 2>&1` | PASS | correct |
| `node .claude/bmad/bin/record.cjs append …` | PASS | correct (pinned) |
| `node .claude/bmad/bin/replay-check.cjs bundle.yaml` | PASS gate — but **not in settings allow-list** (see F2-M4) | friction |
| `git commit -m "simple message"` | PASS | correct |
| writes to `artifacts/**`, `/tmp/**`, `/dev/null` | PASS | correct |
| `git commit -m "rename a -> b"` | **DENY** | **false positive (F2-H2)** |
| `git log --grep="foo>bar"` | **DENY** | **false positive (F2-H2)** |
| `rg "value > 5" src/` | **DENY** | **false positive (F2-H2)** |
| `echo x > src/x.js`, `tee`, `sed -i`, `dd of=`, `node -e`, `sudo node -e`, `>|`, `>src/z.js` (no space) | DENY | correct (test-covered) |

`git add`/`git commit`/`git push` pass the gate but fall out of the narrowed settings allow (prompt, not deny) — consistent with ADR-017 intent (commits are delegated).

### F2-H2 (HIGH) — Quoted `>` in arguments triggers the redirect detector

`generators/hooks/orchestrator-write-gate.cjs.src:192` — the redirect regex scans the raw sub-command including quoted regions. Any command whose quoted argument contains `>` followed by a token that doesn't resolve to an allowed path is denied. `grep`/`rg` are on the settings allow-list and named in the gate's own deny message as permitted, yet `rg "value > 5" src/` is structurally blocked; so is any commit message or grep pattern containing `->`/`>`. Because a PreToolUse deny is absolute, not even human approval can override it.

**Fix:** make the redirect scan quote-aware — track single/double-quote state while scanning (the same discipline `stripComment`/`splitKeyValue` in `bin/replay-check.cjs` already use) and skip `>` operators inside quotes. Add the three verified commands above to the ALLOWED_BASH regression table in `test/hooks.test.js`.

## 2. Ledger integrity (verify item 2)

Spot-checks (F-001, F-009, F-017 vs `git show 9c00390:artifacts/context/findings-register.md`): IDs, titles, status normalization, dates, roles, source citations, D-ID links, severity (carried in body) — all preserved. ID allocation under the lock verified by the 20-process concurrency test and manual runs; `set-status` enforces the per-type state machines including L→promoted `--human-approved` and R→rejected `--reopen-trigger`; envelope validation accepts well-formed and rejects malformed records (good test matrix in `test/record-envelope.test.js`). D-record allocation scans the real `## D-<n> —` heading format of `decision-log.md` correctly (prefixed `D-BRN-*` IDs are ignored by the numeric scan, which is safe).

### F2-H1 (HIGH) — Migration drops the first decision-trail entry of every finding

`scripts/migrate-context-files.js:63` — in `parseDecisionTrail`, the greedy `\s*` after `- \*\*Decision trail:\*\*` consumes the newline AND the leading indentation of the first trail line, so the inner per-entry regex `^\s+-` fails on it. Every finding's first trail entry is dropped; findings with a single entry (15 of 24, including F-017) migrate with `occurrences: []`. The committed `artifacts/context/ledger.md` carries this loss. Verified by running `parseFindings` against the 9c00390 original: only 9/24 records retain any occurrence, and each is missing its `initial` entry.

**Fix:** change `\s*` to `[ \t]*` (or prepend `'\n'` to the captured trail before the inner scan); regenerate `ledger.md` from the git-history original (`git show 9c00390:artifacts/context/findings-register.md`) and recommit. Strengthen the golden test (see coverage report) so it pins exact occurrence counts — the current `>= 1` assertion cannot see this bug.

Related advisories: the occurrence `ref` field stores the trail action verb (`initial`/`reconfirm`) rather than anything citable, and the author capture (`e[2]`) is captured but unused — author and "why" text survive only in git history (F2-L2).

### F2-H3 (HIGH) — `append --status` bypasses the L→promoted human gate

`bin/record.cjs:511-512` (`buildRecord` honors `flags.status`/`input.status` with no gate check) — `append --type L --status promoted` succeeds with no `--human-approved`, minting a promoted lesson directly. Verified empirically (record landed at `status: promoted`). ADR-021 calls this gate "the constitutional line against learned autonomy — non-negotiable"; the mechanical seatbelt only guards the `set-status` door while the `append` door is open.

**Fix:** in `cmdAppend`, restrict the initial status per type: for L allow only `observed`/`recurring` (the migration needs `recurring`) unless `--human-approved <D-ID>` is supplied; symmetric hardening for D-type initial statuses is N/A (prose path). Add a regression test: `append --type L --status promoted` without the flag must exit 1.

### F2-M8 (MEDIUM) — Stale-lock steal TOCTOU can double-grant the lock

`bin/record.cjs:412-419` — two processes that both observe a stale owner race: A reads the stale timestamp, B steals (rm + mkdir + fresh owner), then A's `rmSync` deletes B's brand-new lock and A acquires too — both hold the lock. Low likelihood (requires a 60s-stale lock plus concurrent stealers) but it is exactly the RES-6 class this CLI exists to kill. **Fix:** steal by `renameSync(lockDir, lockDir + '.stale.' + pid)` (atomic claim of the steal) then remove the renamed dir and retry `mkdir`; only one stealer's rename succeeds.

## 3. Replay gate correctness (verify item 3)

Verified behaviors: gated-task detection via `gate: replay` line; ungated tasks pass untouched; gated task with no `evidence:` line blocked with actionable message; missing bundle blocked ("not found" with the convention spelled out); malformed YAML fails loudly (block scalars/tabs throw rather than misread); allow-list-first refusal (command never executed); exit-code comparison; cheap file-exists pre-pass ordered before any exec; engine-missing fails closed; degradation CLI (`replay-check.cjs`) shares the same engine object the hook `require`s, so verdict identity holds by construction. Real `swarm.yaml` (including the new `replay:` block) parses correctly under the constrained reader; `node --test` allowlist entry is honored.

### F2-M1 (MEDIUM) — Gated-path exception handler fails OPEN, contradicting its own comment

`generators/hooks/replay-gate.cjs.src:47-52` — the catch around `onTaskCompleted` exits 0 for ANY throw, with a comment claiming "a gated path that throws is handled inside onTaskCompleted (fail-closed there)" — but no try/catch exists inside `onTaskCompleted`. An engine bug or unexpected throw on a gated task completes unproven work. Current code paths make a throw unlikely (internal catches in `loadReplayConfig`/`evaluateBundle`/`recordRejection`), which is why this is medium not high — but the guard exists precisely for the unexpected. **Fix:** in the catch, re-derive `hasGateMarker(subject + '\n' + desc)` and exit 2 when gated (message: gate errored, completion refused, run `replay-check.cjs` manually).

### F2-M2 (MEDIUM) — Empty `items: []` passes; bundle path is not confined to the repo

`bin/replay-check.cjs:537-539` accepts an empty items list (verdict ok, zero checks), and `:525` (`confinedResolve(...) || path.resolve(bundlePath)`) deliberately un-confines the bundle path itself — a gated task with `evidence: /tmp/empty.yaml` containing `evidence_bundle: {items: []}` passes Tier-0 (verified empirically, both together). Items' paths/cwd ARE confined and commands allowlisted, so this is a trivially-satisfiable-gate problem rather than an execution risk — flagged to the security sibling for the bypass angle. **Fix:** treat empty/absent items as a bundle-schema failure (or minimum: advisory-lint it loudly), and drop the `|| path.resolve` fallback so the bundle must live inside the repo like everything it cites.

### F2-M3 (MEDIUM) — `gated_task_classes` is a dead knob; `review` class not marker-enforced

The knob is defaulted (`utils/config.js:110-117`), validated (`utils/validator.js:59+`), documented in `swarm.yaml` and shipped by `cli/init.js` — and read by nothing. The TaskCreated enforcement (`replay-gate.cjs.src:65`) hardcodes `story-\d+|bug-fix` and does not cover review-verdict tasks, so D-049(e) ("gated classes = story/bug-fix/review") is only two-thirds enforced at creation, and a user editing the knob changes nothing. **Fix:** either wire the hook's class regexes to the config (pass via the engine's `loadReplayConfig`) including a review-task pattern, or delete the knob everywhere until SE-2 wires it. Related false-positive note (low): any task whose subject merely mentions `story-N` (e.g., "Investigate story-4 flakiness") is refused at creation with a message claiming it "looks like a story/bug-fix task".

### F2-M7 (MEDIUM) — `url_citations: blocking` silently behaves as advisory

`bin/replay-check.cjs:457` returns `ok: true` for `blocking` mode with a note that resolution is a follow-on; no HEAD fetch is performed in any mode (design §4.2 check 4 specified an advisory 5s HEAD fetch in v1). The validator accepts `blocking` as a legal value, so a user configuring it gets advisory behavior with no warning. **Fix:** either reject `blocking` in the validator with a "not yet implemented" message, or implement the fetch.

## 5. Test quality (verify item 4) — `test-coverage-report` section

Full suite reverified: **604/604 pass** (3.3s). The new tests are genuinely behavioral — process-spawn against generated hooks with spike-shaped payloads, real child-process concurrency, no mocking of the code under test. Strong points: the F-017 bypass fixtures are exactly the finding's cases; the BLOCKED/ALLOWED Bash matrices; allow-list-refusal asserts the command was *not executed*; the 20-way append race; `validate` run after the race.

Gaps (each is a branch that could regress silently today):

1. **Design-mandated tests absent** (phase2 §4.1/§4.2 test lists): lock steal after stale timeout; atomic-write crash simulation (kill child mid-write, old content intact); command timeout kill; item-level `cwd: ../..` escape (only `confinedResolve` is unit-tested, not the `checkCommand` path).

3. **No test appends a record at a non-initial status** — would have caught F2-H3.
4. **Replay-gate hook branches untested:** engine-missing fail-closed (exit 2); malformed-bundle-at-hook-level; `bug-fix` subject marker enforcement; the outer catch path (F2-M1).
5. **`gated_task_classes` has zero tests** — unsurprising, since nothing reads it (F2-M3).
6. **False-positive protection for the Bash gate is one-sided:** ALLOWED_BASH has no quoted-metacharacter cases, so F2-H2's class had no chance to be caught. Add `rg "a > b"`, `git commit -m "a -> b"`, `git log --grep="x>y"`.
7. `utils/config.js` replay defaults vs `bin/replay-check.cjs` `DEFAULT_REPLAY_CONFIG` are duplicated constants with no drift test — the exact L-003 pattern; the engine can't import package code (self-containment), so add an equality test on the package side.

Fixture provenance: all fixtures in the new tests are constructed inputs to deterministic parsers/gates the team itself specifies (bundles, payloads mirroring the spike-captured TaskCompleted shape, a checked-in copy of the real findings-register). The one external-boundary fixture — the hook payload — derives from the live spike capture. No synthetic-fixture violations.

## 6. Low / advisory findings

- **F2-L1:** `maxIdNum` scans the whole ledger for `id: F-<n>`, including body text — a body quoting an envelope (e.g. "id: F-999") inflates allocation. Anchor to the record block (`^  id:`) or parse sections.
